# План 2: NeoRelay2 — двухканальное управление воротами (открыть/закрыть)

## Задача
Ворота: 3 провода (общий минус + плюс «открыть» + плюс «закрыть»). NeoRelay2 в режиме
прямого управления (входы J1: 3–5 В): GPIO12 → IN1 (открыть), GPIO13 → IN2 (закрыть).
Прошивка ведёт полный цикл: держать канал 1 «время открытия» → пауза «открыто» →
держать канал 2 «время закрытия». Тайминги — со страницы настроек (сейчас они в
localStorage и крутят только анимацию), сохраняются в userdata NVS.

## Решения
- Режим NeoRelay2 — «кнопка» (K1/K2), реле замкнуто пока активен вход; вся логика
  времени в ESP32. WS2812-режим не используем.
- GateControl: state machine IDLE→OPENING→WAITING→CLOSING(+REVERSE_PAUSE 500 мс
  при перезапуске из фазы закрытия — реверс мотора без мёртвой паузы вреден).
  Interlock: оба канала никогда не активны одновременно.
- Повторный сигнал: в OPENING — игнор, в WAITING — продлить «открыто»,
  в CLOSING — стоп закрытия, пауза, снова открытие.
- Новый API GET/POST `/api/gate/config` {openDuration, stayOpen, closeDuration} (сек);
  фронт грузит тайминги из прошивки, сохраняет кнопкой «Сохранить».

## Итерация по железу (2026-07-05)
- NeoRelay2 отменён: вместо него 2× голых реле HF46F-G/5-HS1T (катушка 5 В ~40 мА,
  контакты 7 А/250 В). Катушки — через NPN-ключи (BC337 + 1 кОм в базу + 1N4007
  параллельно катушке), т.к. GPIO не тянет катушку напрямую. Логика активный-высокий,
  прошивка не менялась (те же GPIO12/13).
- Питание всей системы от 220 В на объекте: AC-DC 5 В ≥ 3 А (MEAN WELL RS-15-5 /
  HLK-20M05) → ESP32 VIN + катушки реле + MP1584 (4,0 В → SIM800L).

- Проверено вживую: звонок с номера из белого списка → +CLIP → ATH → полный цикл

# План 1 (сделано): поддержка SIM800L — открытие ворот по звонку/SMS

## Задача
По входящему звонку или SMS с номера из белого списка (страница «Телефоны» в веб-UI)
подавать импульс на ворота. Микрофон/динамик/DTR не используются — только UART.

## Ключевые решения (дизайн)
- **Белый список — единый:** `systemState.phones` (уже есть UI, API `/api/phones`, поля
  `smsEnabled`/`callEnabled`, хранение в `userdata` NVS). Собственный NVS-список из
  заглушки GSMManager удаляем — это дублирование.
- **Связь модулей:** GSMManager не знает о `systemState` — main.cpp передаёт два колбэка:
  `trustedCheck(number, isCall)` (проверка по списку с учётом флагов) и
  `gateOpen(source)` (импульс + счётчик + логи, как в радио-пути).
- **Протокол:** сырые AT-команды по UART2 (Serial2, RX=16, TX=17, 9600).
  TinyGSM не используем — для RING/+CLIP/+CMT достаточно построчного парсера,
  прозрачнее для отладки.
- **Неблокирующая инициализация:** state machine (PROBE → CONFIG → READY) внутри
  `handleGSM()`; при отсутствии модуля — повторная проба каждые 10 с, loop() не
  блокируется (важно: блокировки loop() роняют приём радио).
- **Конфигурация SIM800L:** `ATE0`, `AT+CLIP=1` (АОН), `AT+CMGF=1` (SMS text),
  `AT+CNMI=2,2,0,0,0` (SMS сразу в UART, не копится на SIM).
- **Звонок:** `+CLIP:` → номер; доверенный (callEnabled) → `ATH` (сброс) + ворота;
  чужой → `ATH` + warning в лог. Дедуп повторных +CLIP одного звонка (10 с).
- **SMS:** `+CMT:` → отправитель; доверенный (smsEnabled) → ворота (текст SMS не
  проверяем — любое SMS с доверенного номера открывает). Чужие — warning.
- **Сравнение номеров:** только цифры, по последним 10 цифрам (+7/8/7-форматы дают
  одинаковый хвост).
